# Eval: извлечение брони из сообщения гостя

Замер качества ИИ-шага (`lib/ai/extractBooking.ts`) против базового решения
без ИИ (`lib/ai/baselineExtract.ts`) на наборе, размеченном командой.
Эталонные ответы размечают люди — скрипт их не генерирует.

## Состав набора

- `dataset.jsonl` — по одному примеру на строку, формат —
  `dataset.schema.json`. Сейчас файл пустой: его заполняет команда.
- `audio/<id>.ogg` — записи для примеров `input: "voice"`.
- Требования (методичка ЛЗ 12):
  - **не менее 30 примеров**;
  - на **казахском и русском**, плюс смешанные (`lang: "mixed"`);
  - разные уровни сложности: `easy` — все поля названы явно;
    `hard` — смесь языков, шум, нет времени или имени, исправление в
    середине фразы («в 7, нет, в 8»), разговорные числа («екеуміз»),
    лишние цифры (телефон в тексте);
  - только тексты и записи **участников команды**. Никаких сообщений
    реальных гостей, никаких настоящих телефонов и фамилий.

## Пример строки

```json
{"id":"kk_001","input":"text","text":"Сәлем, ертең кешкі 7-ге 4 адамға үстел керек, атым Айгерім","now":"2026-10-30T15:00","lang":"kk","difficulty":"easy","expected":{"date":"2026-10-31","time":"19:00","party_size":4,"name":"Айгерім","wishes_present":false}}
```

## Правила разметки

- `now` — местные дата и время ресторана в момент сообщения. От него
  считаются «сегодня», «завтра», «в пятницу», поэтому прогон
  воспроизводится в любой день.
- **Дата.** Абсолютная дата `YYYY-MM-DD`, которую имел в виду гость
  относительно `now`:
  - «в пятницу» — ближайшая пятница начиная с сегодняшнего дня (если
    `now` — пятница, то сегодня). Если по смыслу фразы гость явно имеет в
    виду следующую неделю («в следующую пятницу»), размечайте её;
  - «на выходных» без уточнения — `null`: гость дату не назвал.
- **Время.** `HH:MM` в 24-часовом формате: «кешкі 7» → `19:00`. Если
  назвали только часть суток («вечером») — `null`.
- **Число гостей** — вместе с самим гостем («екеуміз» → 2).
- **Имя** — как гость назвал себя, без фамилии, если её не было. Регистр
  при сравнении не важен.
- **Отсутствующее поле** — всегда `null`, а не пустая строка и не
  «догадка». Именно на таких полях меряется доля выдумок.
- **Исправление в середине фразы** — размечайте последнее значение.
- `wishes_present` — `true`, если гость явно о чём-то попросил (у окна,
  детский стул, день рождения), иначе `false`.
- Для голосовых примеров в `text` запишите, что **на самом деле
  сказано**. По нему раннер отделяет ошибки распознавания речи от ошибок
  извлечения.

## Запуск

Нужен `GROQ_API_KEY` (в shell или `.env.local`). База не нужна: лог
`ai_requests` в офлайн-прогоне пропускается.

```bash
npx tsx evals/booking/run.ts
npx tsx evals/booking/run.ts --model openai/gpt-oss-20b --prompt-version extract_booking_v2
```

Без `--model` используется `GROQ_LLM_MODEL` (по умолчанию
`openai/gpt-oss-20b`). `--prompt-version` должен совпадать с
`PROMPT_VERSION` в коде: промпт — это код, его версию меняют вместе с
текстом. Параметры фиксированы: `temperature 0`, `seed 42`.

Вручную через GitHub: Actions → **Eval booking extraction** → Run
workflow. Результаты прикрепляются к прогону артефактом, сводка видна на
странице прогона.

## Что считается

Отдельно для ИИ и для базового решения, на одном и том же тексте:

- точность по каждому полю (`date`, `time`, `party_size`, `name`,
  `wishes_present`) — в целом и в разрезе `kk`/`ru`/`mixed` и
  `easy`/`hard`;
- доля примеров, где верны все четыре основных поля;
- **доля выдумок** — поле заполнено, а в эталоне `null`;
- для голосовых — сколько ошибок вызвано распознаванием: ошибка на
  расшифровке исчезает, если подать модели эталонный `text`;
- средняя и p95 задержка (распознавание, извлечение), суммарные токены и
  секунды аудио — для расчёта стоимости (`cost.md`).

Сырые ответы — `results/<дата>_<модель>_<версия промпта>.jsonl`, сводка —
`…_summary.md`. В сводке записаны модель, версия промпта, дата прогона и
параметры: без них замер по методичке не засчитывается.
