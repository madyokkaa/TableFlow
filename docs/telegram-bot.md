# Telegram-бот бронирования с ИИ

Гость пишет боту ресторана текстом или голосом («Сәлем, ертең кешкі 7-ге
4 адамға үстел керек, атым Айгерім»). Бот собирает дату, время, число
гостей и имя, показывает сводку, берёт телефон из контакта Telegram и
создаёт бронь в статусе «Ожидает». Хостес подтверждает её в панели, и
бот сообщает гостю.

ИИ делает ровно два шага:

1. голос → текст (Groq, `whisper-large-v3`);
2. текст → поля брони в JSON (Groq, `openai/gpt-oss-20b`).

Всё остальное — обычный код: проверка дат и часов работы
(`lib/ai/bookingFields.ts`), поиск стола (`lib/availability.ts`),
создание брони (RPC `create_reservation`), уведомления. Модель не пишет в
базу и не считает доступность. Если Groq недоступен или вернул не тот
JSON, поля извлекает базовое решение без ИИ (`lib/ai/baselineExtract.ts`).

## Подключение

1. **Бот.** В Telegram откройте @BotFather → `/newbot` → получите токен.
   Для тестов заведите второго бота: Preview-деплой должен работать со
   своим ботом, а не с рабочим.
2. **Groq.** Создайте ключ API в консоли Groq.
3. **Переменные в Vercel** (Settings → Environment Variables). Production
   и Preview задаются отдельно; в Preview — токен тестового бота и
   тестовый проект Supabase.

   | Переменная | Значение |
   | --- | --- |
   | `TELEGRAM_BOT_TOKEN` | токен от @BotFather |
   | `TELEGRAM_WEBHOOK_SECRET` | случайная строка 32+ символов из `A-Z a-z 0-9 _ -` |
   | `GROQ_API_KEY` | ключ Groq |
   | `GROQ_STT_MODEL` | необязательно, по умолчанию `whisper-large-v3` |
   | `GROQ_LLM_MODEL` | необязательно, по умолчанию `openai/gpt-oss-20b` |
   | `GROQ_STT_PROMPT` | необязательно: своя подсказка Whisper со словарём (по умолчанию — образец фраз брони на kk/ru из `lib/ai/groq.ts`; пустое значение — без подсказки) |
   | `AI_BOOKING_ENABLED` | `1` — работает, `0` — аварийно выключен (см. ниже) |
   | `RESTAURANT_TIME_ZONE` | IANA-пояс ресторана, например `Asia/Almaty`. Без него бот считает «сегодня» в `Europe/Moscow` (`FALLBACK_TIME_ZONE`) |
   | `RESTAURANT_NAME` | необязательно, название в приветствии бота |
   | `NEXT_PUBLIC_SITE_URL` | адрес сайта `https://…` без `/` на конце: ссылки из бота и адрес вебхука |
   | `CRON_SECRET` | уже используется ежедневной очисткой; нужен и напоминаниям |

   Секрет можно сгенерировать так:
   ```bash
   node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
   ```
4. **Миграции** — сначала на тестовом проекте, затем на рабочем:
   ```bash
   npx supabase db push --db-url "$TEST_SUPABASE_DB_URL"
   ```
   ```bash
   npx supabase db push --db-url "$SUPABASE_DB_URL"
   ```
5. **Вебхук.** После деплоя, с переменными нужного окружения в
   `.env.local` или в shell:
   ```bash
   npx tsx scripts/telegram-set-webhook.ts
   ```
   Скрипт ставит вебхук на `NEXT_PUBLIC_SITE_URL/api/telegram` с
   `secret_token`, регистрирует команды `/start` и `/cancel` и печатает
   `getWebhookInfo`.
6. **Напоминания за час.** В SQL Editor каждого проекта Supabase
   выполните `supabase/manual/schedule_reminders.sql`, подставив адрес
   деплоя и `CRON_SECRET` этого окружения. Там же — команды проверки
   (`cron.job_run_details`, `net._http_response`) и отключения
   (`cron.unschedule`).

## Как проверить вручную

На тестовом боте и тестовом проекте:

1. **Голос, казахский.** `/start` → «Келісемін / Согласен» → голосовое
   «ертең кешкі жетіге төрт адам, атым Айгерім» → сводка с датой
   словами → ✅ → «Поделиться номером» → «Өтінім қабылданды ✅». В панели
   у брони бейдж «Telegram» с иконкой Telegram и блок «Распознано ИИ — проверьте».
2. **Текст, русский.** «Завтра в 19:30 на двоих, меня зовут Дмитрий» →
   сводка на русском.
3. **Нет времени.** «Завтра вчетвером» → бот спрашивает «На какое
   время? Как вас зовут?». После трёх непонятых ответов — ссылка на сайт.
4. **Занято.** Займите стол на сайте на то же время → бот предлагает до
   трёх ближайших свободных времён кнопками; выбор времени создаёт бронь.
5. **Исправление.** На сводке нажмите ✏️ → «Не в семь, а в восемь» →
   новая сводка с 20:00; остальные поля сохранились.
6. **Подтверждение.** В панели подтвердите бронь → гостю приходит
   «Брондау расталды ✅ / Бронь подтверждена ✅» с залом. Перенос времени
   и отмена персоналом тоже приходят гостю.
7. **Напоминание.** Подтвердите бронь на время через ~1 час → в течение
   10 минут после попадания в окно 45–75 минут приходит напоминание.
   Проверка: `select status_code, content from net._http_response order by created desc limit 5;`
8. **Отмена гостем.** Кнопка «Бас тарту / Отменить бронь» под заявкой →
   бронь «Отменена», отменил гость. Из другого чата отменить нельзя.
9. **Аварийное отключение.** `AI_BOOKING_ENABLED=0` → любое сообщение →
   «бронирование через бот временно недоступно» и ссылка на сайт.

## Качество распознавания

- **Голос.** Whisper получает подсказку (`prompt`) — образец фраз брони на
  казахском, русском и вперемешку. Она тянет распознавание к казахскому
  написанию и словам, которые гости говорят чаще всего. В ответ на
  голосовое бот показывает «🎤 «…»» — что он расслышал, чтобы гость сразу
  заметил ошибку.
- **Текст → поля.** Промпт `extract_booking_v2` знает числа словами
  («жетіге», «сегізде», «жеті жарымда», «к семи», «в половине восьмого»)
  и типичные ошибки расшифровки. Базовое решение без ИИ понимает те же
  обороты.
- Мерить улучшения — eval (`evals/booking/`): одинаковый набор, разные
  версии промпта или модели.

## Какие данные куда уходят

Только факты из кода.

- **Telegram.** Сообщения гостя и ответы бота проходят через серверы
  Telegram. От Telegram бот получает id чата, язык интерфейса, текст или
  голосовое и — только после нажатия «Поделиться номером» — телефон.
  Принимается только собственный контакт гостя (`contact.user_id` равен
  отправителю).
- **Groq.** Получает текст сообщения или голосовое (для распознавания) и
  текст для извлечения полей. Гость узнаёт об этом в приветствии до
  согласия; без согласия бот ничего не отправляет в Groq и брони не
  создаёт.
- **База, `reservations`.** Имя, телефон (из контакта), число гостей,
  дата и время, `source = 'telegram_ai'`, `ai_transcript` (что гость
  написал или сказал, до 2000 символов), `telegram_chat_id`, `consent_at`,
  отметки об отправленных подтверждении и напоминании.
- **База, `telegram_sessions`.** Состояние диалога и черновик брони (те
  же поля, пока бронь не создана), язык, время согласия. Сессия без
  активности 30 минут начинается заново; согласие и язык сохраняются.
- **База, `telegram_updates`.** Только `update_id` — защита от повторной
  доставки; хранятся двое суток.
- **База, `ai_requests`.** Модель, версия промпта, успех или код ошибки,
  задержка, токены, секунды аудио. Текста сообщений там нет.
- **Не хранится:** голосовые файлы (только в памяти на время запроса).
  Логи сервера содержат только идентификаторы, коды ошибок и длительности
  — без текста сообщений, расшифровок, имён, телефонов и полного id чата
  (лимит частоты хранит HMAC от id чата).
- **Удаление данных** (`/privacy`, `erase_guest_data`): при обезличивании
  брони стираются и `ai_transcript`, `telegram_chat_id`, а сессия этого
  чата удаляется.

## Лимиты бесплатных тарифов

Конкретные цифры лимитов здесь намеренно не приведены: они меняются.
Актуальные лимиты Groq — на официальной странице лимитов в документации
Groq (Rate Limits).

Если лимит Groq исчерпан или сервис недоступен:

- **текст** разбирает базовое решение без ИИ; если и оно ничего не
  поняло — бот честно предлагает забронировать на сайте;
- **голос** без Groq распознать нельзя — бот просит написать текстом или
  забронировать на сайте.

Чтобы один чат не сжёг квоту, бот принимает не больше 20 сообщений за
10 минут с одного чата (`RATE_LIMIT_TELEGRAM_CHAT`, формат
`<запросов>/<секунд>`). На переполнение он отвечает один раз и дальше
молчит до конца окна.

## Аварийное отключение

`AI_BOOKING_ENABLED=0` в Vercel → Redeploy. Бот перестаёт вызывать Groq и
создавать брони и на любое сообщение отвечает ссылкой на сайт.
Подтверждения, отмены и напоминания по уже созданным броням продолжают
работать.
